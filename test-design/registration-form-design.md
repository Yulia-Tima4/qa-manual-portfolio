# Тест-дизайн формы регистрации — Lomonosov.school

## 1. Цель работы

Цель — показать, как с помощью техник тест-дизайна можно подготовить проверки формы регистрации.

В работе рассмотрены четыре техники:

- классы эквивалентности;
- граничные значения;
- таблица принятия решений;
- попарное тестирование.

## 2. Описание формы

Форма регистрации на Lomonosov.school содержит семь обязательных полей:

1. Фамилия
2. Имя
3. Телефон
4. Email
5. Ник в Telegram
6. Аккаунт в VK
7. Пароль

Также есть чекбокс согласия на обработку персональных данных.

Все семь полей должны быть заполнены. Отдельно необходимо проверить, можно ли отправить форму без согласия.

**Важно:** точные правила проверки формата и длины полей в этой работе не указаны. Поэтому некоторые примеры приведены для демонстрации техник тест-дизайна.

## 3. Классы эквивалентности

### Что это такое?

Классы эквивалентности — это разделение данных на группы, которые можно проверять похожим способом.

Например, для поля Email можно проверить корректный адрес, пустое поле и адрес с ошибкой. Нет необходимости придумывать десятки похожих значений, если они проверяют одно и то же условие.

### Примеры проверок

| Поле | Тестовые данные | Что проверяем |
|---|---|---|
| Фамилия | Иванова | Поле принимает текст |
| Фамилия | Пустое значение | Поле обязательно для заполнения |
| Фамилия | Только пробелы | Как обрабатывается пустой по смыслу ввод |
| Имя | Анна | Поле принимает текст |
| Имя | Пустое значение | Поле обязательно для заполнения |
| Телефон | `+79991234567` | Как обрабатывается номер телефона |
| Телефон | `123` | Проверка короткого номера |
| Телефон | Пустое значение | Поле обязательно для заполнения |
| Email | `user@example.com` | Проверка корректного формата |
| Email | `userexample.com` | Проверка адреса без `@` |
| Email | Пустое значение | Поле обязательно для заполнения |
| Ник в Telegram | `@test_user` | Проверка заполненного поля |
| Ник в Telegram | Пустое значение | Поле обязательно для заполнения |
| Аккаунт в VK | `https://vk.com/example` | Проверка заполненного поля |
| Аккаунт в VK | Пустое значение | Поле обязательно для заполнения |
| Пароль | `TestPass123!` | Проверка заполненного поля |
| Пароль | `Ab1!` | Проверка короткого пароля |
| Пароль | Пустое значение | Поле обязательно для заполнения |

Для поля «Имя» также можно проверить ввод только пробелов, цифр и специальных символов. Для ника в Telegram и аккаунта VK необходимо уточнить, какие форматы принимает форма.

### Вывод

С помощью классов эквивалентности я подобрала примеры данных для проверки обязательности полей и обработки разных значений.

## 4. Граничные значения

### Что это такое?

Граничные значения — это проверка данных около минимально и максимально допустимого размера.

Например, если пароль должен содержать от 8 до 20 символов, нужно проверить значения длиной 7, 8, 9, 19, 20 и 21 символ.

**Примечание:** ограничения от 8 до 20 символов приведены только для примера. Это не подтверждённые требования Lomonosov.school.

### Пример проверки длины пароля

| Длина пароля | Что проверяем |
|---|---|
| 7 символов | Значение короче минимально допустимого |
| 8 символов | Минимально допустимая длина |
| 9 символов | Значение чуть больше минимума |
| 19 символов | Значение чуть меньше максимума |
| 20 символов | Максимально допустимая длина |
| 21 символ | Значение длиннее максимума |

Если система использует такие ограничения, слишком короткий и слишком длинный пароль должны обрабатываться согласно правилам валидации.

### Пример проверки длины фамилии

Предположим, что допустимая длина фамилии — от 1 до 50 символов. Это условный пример.

| Длина фамилии | Что проверяем |
|---|---|
| 0 символов | Пустое обязательное поле |
| 1 символ | Минимальная длина |
| 2 символа | Значение чуть больше минимума |
| 49 символов | Значение чуть меньше максимума |
| 50 символов | Максимальная длина |
| 51 символ | Значение длиннее максимума |

### Вывод

Граничные значения помогают проверить, правильно ли система обрабатывает данные на границах допустимой длины. Для реального тестирования нужно знать ограничения каждого поля.

## 5. Таблица принятия решений

### Что это такое?

Таблица принятия решений помогает проверить, как форма ведёт себя при разных сочетаниях условий.

В этом примере проверяются два условия:

- заполнены ли все семь обязательных полей;
- отмечен ли чекбокс согласия на обработку персональных данных.

### Таблица проверок

| № | Все поля заполнены | Согласие отмечено | Ожидаемый результат |
|---|---|---|---|
| 1 | Да | Да | Форма проходит проверку обязательности полей и согласия |
| 2 | Да | Нет | Форма не должна отправляться успешно |
| 3 | Нет | Да | Форма не должна отправляться успешно |
| 4 | Нет | Нет | Форма не должна отправляться успешно |

В первом случае форма проходит только проверку обязательных полей и согласия. Для успешной регистрации также могут требоваться корректные форматы введённых данных.

### Дополнительные проверки

Чтобы убедиться, что обязательны все семь полей, нужно проверить каждое отдельно:

- оставить пустой фамилию, остальные поля заполнить;
- оставить пустое имя;
- оставить пустой телефон;
- оставить пустой Email;
- оставить пустой ник в Telegram;
- оставить пустой аккаунт VK;
- оставить пустой пароль.

В каждом случае форма не должна успешно отправляться, если соответствующее поле обязательно.

### Вывод

Таблица помогает проверить основные сочетания заполненности полей и состояния чекбокса. Дополнительные проверки позволяют убедиться, что обязательность действует для каждого поля отдельно.

## 6. Попарное тестирование

### Что это такое?

Попарное тестирование помогает уменьшить количество тестов, когда нужно проверить сочетания нескольких параметров.

Вместо проверки всех возможных комбинаций подбирается набор тестов, в котором каждая пара вариантов встречается хотя бы один раз.

### Пример

Рассмотрим три параметра:

- фамилия: заполнена или пустая;
- Email: корректный или некорректный;
- пароль: соответствует условным требованиям или не соответствует им.

У каждого параметра два варианта. Если проверить все сочетания, получится:

2 × 2 × 2 = 8 комбинаций.

Для демонстрации попарного тестирования можно использовать четыре комбинации:

| № | Фамилия | Email | Пароль |
|---|---|---|---|
| 1 | Заполнена | Корректный | Соответствует требованиям |
| 2 | Заполнена | Некорректный | Не соответствует требованиям |
| 3 | Пустая | Корректный | Не соответствует требованиям |
| 4 | Пустая | Некорректный | Соответствует требованиям |

В этих четырёх тестах встречаются все сочетания значений для каждой пары параметров.

Например, для пары «Фамилия + Email» проверяются все четыре варианта:

- заполненная фамилия и корректный Email;
- заполненная фамилия и некорректный Email;
- пустая фамилия и корректный Email;
- пустая фамилия и некорректный Email.

Так же проверяются пары «Фамилия + Пароль» и «Email + Пароль».

В результате для этого примера достаточно четырёх комбинаций вместо восьми.

**Важно:** это упрощённый пример. Он не заменяет отдельные проверки всех семи полей, форматов данных и граничных значений.

### Вывод

Попарное тестирование позволяет уменьшить количество комбинаций, которые нужно проверить, сохраняя покрытие всех пар значений выбранных параметров.

## 7. Итог

В работе рассмотрены четыре техники тест-дизайна:

- **Классы эквивалентности** — помогают выбрать разные типы тестовых данных.
- **Граничные значения** — помогают проверить минимальные и максимальные ограничения.
- **Таблица принятия решений** — помогает проверить сочетания нескольких условий.
- **Попарное тестирование** — помогает уменьшить количество комбинаций параметров.

Эти техники можно использовать вместе, чтобы подготовить проверки формы регистрации и не ограничиваться только вводом корректных данных.

## 8. Ограничения работы

- Документ показывает подготовку тестов, а не результаты фактически выполненных проверок.
- Примеры ограничений длины являются условными.
- Перед реальным тестированием необходимо уточнить правила валидации каждого поля.
- Результаты выполнения тестов и найденные дефекты в документ не включены.
